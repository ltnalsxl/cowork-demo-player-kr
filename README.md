# Copilot Cowork 시나리오 데모

Cowork 실행 기록을 실제 화면과 같은 모습으로 재생하고, 작업이 끝나면 `/cost`로 확인한
크레딧을 함께 보여주는 데모 사이트입니다. 고객에게 "이 일을 시키면 얼마가 드나"를
말이 아니라 화면으로 보여주는 것이 목적입니다.

> **산출물에 대하여**
> 이 저장소의 문서와 리포트는 Copilot Cowork가 만든 결과물을 그대로 담은 것입니다.
> 제품이 어떻게 동작하는지 보여주려는 자료이지 사실 확인을 거친 조사 자료가 아닙니다.
> 시장 분석 회차에 실제 기업명이 나오지만 공개된 자료를 근거로 AI가 정리한 내용이며,
> 어떤 조직의 공식 견해도 아닙니다. 인용하거나 의사결정에 쓰지 마십시오.
> 크레딧 수치는 이 데모의 회차를 직접 돌려 잰 값이고 상대 비교용입니다.

## 실려 있는 시나리오

|---|---|---|---|---|
| `tc04-sonnet` | 딥리서치 | Sonnet 5 · 보통 | 2,126 | 65분. 편집을 잘게 쪼개다 14번 실패하고 재시도 |
| `tc04-terra` | 딥리서치 | GPT 5.6 Terra · 매우 높음 | 1,614 | 87분. 표지 이미지를 직접 생성. 3단계 중 1개 취소됨 |

앞의 둘은 모델 비교가 목적이고, 뒤의 여섯은 실습용입니다.
**크레딧을 재지 않은 회차는 싣지 않습니다.** 없는 값을 비워 두고 보여 주느니
빼는 편이 낫다고 봤습니다.

같은 프롬프트를 조건만 바꿔 돌린 회차가 셋 있습니다(TC-04, 실습-03, 실습-06).
**TC-04는 홈에 하나만 세우고 그 안에서 탭으로 오갑니다.** 모델이 바뀌면
로그 전체가 달라져서 답변만 갈아 끼울 수 없기 때문입니다. 탭에 크레딧이 함께 붙습니다.
실습-03과 실습-06은 빈 계정 쪽에 볼 것이 없어 **데이터가 많은 쪽 하나만 재생하고
계정 차이는 크레딧 표에만** 남겼습니다.

두 축을 각각 보여줍니다.

- **TC-04**는 모델을 바꿨을 때의 차이입니다. 비싼 쪽이 더 나은 결과를 내지 않았습니다.
  가장 비싼 Sonnet 5(2,126)의 문서가 가장 얇고(14,664자, 표 1개),
  가장 싼 Terra(1,614)의 문서가 가장 두껍습니다(26,411자, 표 6개).
- **실습-03**은 계정만 바꿨을 때 값이 거의 안 움직이는 경우입니다. 95와 107로 붙습니다.
  읽고 메시지 하나 보내는 작업은 데이터가 늘어도 값이 잘 안 변합니다.
  반대로 **실습-06**은 같은 방식으로 계정만 바꿨는데 195와 755로 3.9배 벌어집니다.
  읽을 양이 20배가 되고 만들 것도 늘었기 때문입니다.
- **실습-01**는 **승인 흐름**과 **멀티턴**을 보여줍니다. 한 작업 창에서 네 번 시켰습니다.
  1. 출입기록 600건에서 퇴근 태그 누락 164건을 찾아 요약하고, 편집 가능한 초안을 띄워
     승인을 받은 뒤 메일을 보냈습니다.
  2. 이어서 `frontend-design` 커스텀 스킬을 만들라고 시켰고, 이번에는 **파일 복사 승인 카드**가
     떴습니다. 복사할 경로와 덮어쓰기 여부를 표로 보여주고 승인을 받은 뒤에야 반영됩니다.
     승인 카드가 메일 전용이 아니라는 걸 보여주는 자리입니다.
  3. "95점 이상이 되도록 해줘"로 다시 시켰고 품질 점수가 79점에서 98점으로 올라갔습니다.
     견고성 항목이 9점에서 25점으로 바뀐 게 대부분입니다.
  4. 그 스킬을 실제로 불러 리포트를 다시 뽑았습니다. **첫 호출이 실패합니다.**
     방금 만든 스킬이라 세션에 아직 안 실려서인데, Copilot이 막히지 않고
     폴더에서 `SKILL.md`를 직접 읽어 지침대로 따릅니다. 실패해도 이어가는 모습이
     그대로 남아 있어 실습에서 보여주기 좋습니다.
  5. "밝은 계열의 깔끔한 디자인으로" 같은 리포트를 한 판본 더 만들게 했습니다.
     데이터와 구조는 그대로 두고 톤만 바꿉니다. 같은 스킬로 다크와 라이트 두 판본을
     나란히 놓고 볼 수 있습니다.

  다섯 번을 합쳐 **789크레딧**입니다. `/cost`는 프롬프트 하나가 아니라 그 작업 전체를 셉니다.
  12분 사이에 세 번 찍은 값(566 → 576 → 789)이 대화 안에 그대로 남아 있어, 누적이라는 걸
  화면으로 보여줄 수 있습니다.
  작업 영역의 기술 및 플러그 인에는 만든 스킬(`frontend-design`)과 **기술 관리** 버튼이 함께 뜹니다.
  이 회차는 짧아서 단계 계획 자체를 세우지 않았고, 그래서 작업 영역에 단계 칸이 없습니다.
  **사고 과정이 도구 묶음 안에 끼어 나오고 본문이 영어입니다.** 실제 화면 그대로 뒀습니다.
- **실습-02**은 **한 번 시켜 산출물 넷을 받는** 실행입니다. 정책 문서 둘과 CSV 둘을 첨부하고
  Word 문서 둘, Excel 하나, 메일 초안 하나를 한 번에 요구했습니다. 작업 영역에 단계 넷이
  잡히고 끝까지 갑니다. **Word 편집이 15번 거부됩니다.** 표를 만든 직후 셀에 값을 넣으려 하면
  자주 막히는데, 그때마다 문서 구조를 다시 읽고 더 작은 배치로 나눠 넣습니다.
  고객이 실제로 겪을 패턴이라 그대로 남겼습니다.

  마지막에 **주소록 조회가 빈손으로 돌아옵니다.** CISO를 못 찾자 짐작해 채우지 않고
  수신자를 비운 채 초안으로 저장합니다. **초안 카드에 받는 사람이 비어 있고 보내기 버튼이
  회색으로 잠깁니다.** 모르면 비워 두는 모습을 보여주는 자리입니다.
  두 번째 턴에서 "이 메일과 파일들을 나에게 보내주세요"라고 시키자, 저장된 초안을 다시
  꺼내 봤지만 수신자가 남아 있지 않아 새 메일로 보내고 그 사실을 밝힙니다.
  "파일에 없는 지적사항, 담당자, 정책 내용을 지어내지 마세요"라는 지시가 프롬프트에 있고,
  답변의 모든 숫자와 위험ID가 첨부 CSV로 추적됩니다. 첫 턴에 **1,130크레딧**입니다.
- **실습-03**는 **한 번 시키고 끝나지 않는** 실행입니다. "평일 아침 7시 30분에 브리핑을
  Teams로 보내 줘"라는 두 줄짜리 요청을 Cowork가 열 몇 줄짜리 작업 설명으로 늘려
  **되풀이 작업 승인 카드**를 띄웁니다. 반복 주기와 실행 위치를 고르고, "지금 한 번 실행"에
  체크한 채 예약하면 늘어난 설명이 그대로 두 번째 프롬프트가 되어 즉시 한 번 돕니다.
  승인 뒤에는 작업 영역에 **예약된 작업** 칸이 남습니다.

  회의 4건과 회신 대기 3건을 찾아 한 화면에 담고, 근거가 없는 준비물은 `확인 필요`로
  남깁니다. 메일이 아니라 **Teams 채팅 승인 카드**라 제목 칸이 없고 버튼이
  "Post message 항상 허용"입니다. 이 버튼을 누르면 작업 영역에 **항상 허용됨** 칸이
  생기고, 다음부터는 승인 없이 나갑니다.

  같은 프롬프트를 **일정이 0건인 계정**에서도 돌렸습니다. 그쪽은 캘린더가 비자
  "등록된 일정 없음"으로 적고 끝냈고, 화면에 볼 것이 없어 재생에는 싣지 않았습니다.
  **크레딧은 95와 107입니다.** 데이터가 크게 차이 나는데 12밖에 벌어지지 않습니다.
  실습-06 밀린 메일 정리가 같은 조건에서 195와 755로 3.9배 벌어진 것과 대비됩니다.
  차이를 만드는 건 읽을 데이터의 양만이 아니라 **문서를 만드느냐**입니다. 브리핑은 읽고
  메시지 하나를 보내고 끝나서, 계정이 바뀌어도 값이 거의 그대로입니다.
  되풀이로 돌려도 부담이 크지 않다는 뜻이라 자동화를 권할 때 쓸 수 있는 숫자입니다.
- **실습-04**는 유일하게 **대화 밖에서 시작하는** 회차입니다. 사용자 지정에서 스킬을 올리고,
  슬래시로 불러 씁니다. 설치 여덟 단계를 캡처가 아니라 같은 방식으로 다시 그려 재생에
  넣었습니다. 누른 자리에 붉은 테두리가 갑니다.
  1. 사이드바에서 **사용자 지정**을 연다. 플러그인 탭이 먼저 뜬다
  2. **기술** 탭으로 넘어간다. 플러그인은 외부 도구에 연결하고 기술은 일하는 방법을 가르친다
  3. **추가 → 기술 업로드**를 고른다
  4. 받는 형식은 `.MD`, `.ZIP`, `.SKILL`. 참고 파일이 딸린 스킬은 폴더째 압축해 올린다
  5. 만들어 둔 `skill-korean-proofread.zip`을 고른다
  6. 내 기술 맨 위에 들어온다
  7. 눌러서 안내를 확인한다. 스킬은 결국 지침 문서라 화면에서 그대로 읽힌다
  8. 올린 파일은 **내 OneDrive** `문서/Cowork/skills/korean-proofread/`에 남는다.
     숨은 저장소가 아니라 내 폴더다

  설치가 끝난 뒤에야 프롬프트가 나옵니다. 이 회차만 프롬프트 말풍선이 재생 도중에
  등장합니다(`promptAt`). 이어서 이중피동과 상투구를 일부러 심어 둔 사내 공지를
  `/korean-proofread`로 교열시킵니다.

  **여기서 모델을 바꾸면 답변이 바뀝니다.** 같은 공지를 같은 스킬로 모델만 바꿔
  새 작업 다섯 개에서 돌렸고, 노력은 모델별 기본값을 그대로 뒀습니다.

  | 모델 | 노력 | 크레딧 | 등급 | 지적 | 자체 변경률 |
  |---|---|---|---|---|---|
  | Sonnet 5 | 보통 | 25 | D | 🔴7 🟡6 🔵1 | 30~35% |
  | GPT 5.6 Terra | 매우 높음 | 26 | C | 🔴4 🟡4 | 보통 |
  | Opus 5 | 보통 | 50 | D | 🔴6 🟡7 🔵1 | 약 25% |
  | GPT 5.6 Sol | 보통 | 52 | D | 🔴7 🟡6 | 약 39.1% |
  | GPT 5.5 | 매우 높음 | 76 | D | 🔴8 🟡9 🔵2 | 약 49% |

  읽어 낼 것이 셋입니다.

  1. **핵심 판정은 흔들리지 않습니다.** 다섯 모두 이중피동 다섯 곳과 주어·서술어
     비호응을 잡았습니다. 규칙을 문서로 못 박아 두면 모델이 달라도 결과가 수렴합니다
  2. **갈리는 건 얼마나 손대느냐입니다.** Opus 5는 25%만 고쳐 원문 골격을 남겼고,
     GPT 5.5는 49%를 고쳐 문단 구조까지 바꿨습니다. 같은 원문에 등급도 C와 D로 갈립니다
  3. **비싼 쪽이 더 낫지 않습니다.** 가장 적게 든 Sonnet 5(25)와 Terra(26)가
     가장 많이 든 GPT 5.5(76)보다 못하지 않습니다. 논리 구멍(이관 종료 2/28과
     오픈 3/2 사이 3월 1일)을 짚은 건 Opus 5와 Terra뿐입니다
- **실습-05**은 **두 번째 커스텀 스킬**이 나오는 자리입니다. `company-template`은
  지침만이 아니라 서식 파일(`weekly-report-form.docx`)을 함께 들고 있어, 매번 같은
  모양의 문서가 나오게 합니다. 스킬이 규칙에 더해 자산도 나른다는 걸 보여줍니다.

  내용 면에서는 **앞 실습의 결과가 그대로 이번 주 업무가 됩니다.** 실습-01에서 만든
  출입기록 점검과 실습-02에서 만든 ISMS-P 제출 자료가 주간보고의 두 프로젝트로
  올라옵니다. 캘린더와 Teams는 조회 결과가 없어 채우지 않고 「확인 필요」로 남겼고,
  뉴스레터와 사이트 공유 알림은 프롬프트 지시대로 근거에서 뺐습니다.
  네 단계를 끝까지 밟아 **271크레딧**입니다.
- **실습-06**은 2주 치 받은 편지함과 Teams 멘션을 함께 훑어 세 갈래로 나누고,
  Excel 추적표 하나와 회신 초안을 만듭니다. "회신은 초안에서 멈추고 발송하지 마세요"가
  프롬프트에 있고, 초안함까지만 갑니다. 400건에서 38건을 걸러 내고, 오래 기다린 순서로
  세웁니다. 답장 대신 Teams 멘션으로 온 요청도 대기 항목으로 셉니다.
  초안에서 본인이 정해야 하는 값(고객사, 일자, 회신 예정일)은 대괄호로 비워 둡니다.

  같은 프롬프트를 **2주 치가 20건인 계정**에서도 돌렸습니다.

  | | 훑은 것 | 남긴 것 | 시트 | 초안 | 크레딧 |
  |---|---|---|---|---|---|
  | 편지함이 얇은 계정 | 20건 | 7건 | 2개 | 2건 | 195 |
  | 편지함이 두꺼운 계정 | 400건 | 38건 | 4개 | 5건 | 755 |

  **3.9배 벌어집니다.** 프롬프트가 "최대 5건"을 허용했는데도 얇은 쪽은 **2건에서
  멈췄습니다.** 답을 기다리는 건이 둘뿐이라 셋을 지어내지 않습니다.

세 딥리서치 회차는 모두 **직전 회차가 만든 파일을 OneDrive에서 지우고** 돌렸습니다.
앞 회차의 산출물을 읽어 재활용하면 독립 시행이 깨지기 때문입니다. 이 조건은 비용 패널의
"측정 조건"에 그대로 표시됩니다.

### 자동·보통으로 잰 회차를 한 줄에 세우면

비교 대상이 뚜렷한 회차(모델 비교, 계정 비교)는 각자 표를 쓰고, 나머지는 이 사다리를
공유합니다. 모델과 노력을 고정하고 작업만 바꾼 값이라 서로 견줄 수 있습니다.

| 회차 | 크레딧 | 무엇을 했나 |
|---|---|---|
| 아침 브리핑 | 107 | 읽고 Teams 메시지 하나 · 산출물 없음 |
| 주간보고 · 사내 표준 서식 | 271 | 서식 확인 + Word 1건 + Teams 요약 |
| 밀린 메일 정리 | 755 | 400건 훑음 + Excel 1건 + 회신 초안 5건 |
| 출입기록 점검 · 스킬 만들기 | 789 | 5턴 누적 · 메일 + 커스텀 스킬 + HTML 4개 |
| ISMS-P 심사 대응 | 1,130 | 문서 4종 · Word 편집 15회 거부 |

맨 위와 맨 아래가 10.6배입니다. 값을 가르는 것은 읽을 양 하나가 아니라 **읽을 양과
만들 것이 함께 작용한 결과**입니다. 아침 브리핑은 읽고 메시지 하나를 보내고 끝나서
계정을 바꿔도 95와 107로 붙지만(실습-03), Excel과 초안까지 만드는 밀린 메일 정리는
같은 조건에서 195와 755로 3.9배 벌어집니다(실습-06).

## 화면 흐름

1. 홈에서 "다음 재생 항목"의 시나리오를 고른다. 크레딧이 함께 보여 고르기 전에 가늠할 수 있다
2. 사용자 프롬프트가 뜬 상태로 시작한다
3. 재생을 누르면 사고 과정, 도구 호출, 서브 에이전트, 중간 보고가 순서대로 나온다
4. 오른쪽 작업 영역의 단계 표시가 함께 진행된다
5. 마지막에 산출물 카드가 뜨고 이어서 `/cost` 결과가 나온다
6. 하단 모델 선택기를 바꾸면 그 모델로 측정한 실측값으로 비용이 다시 계산된다

산출물 카드나 작업 영역의 출력 항목을 누르면 Word 페이지, 슬라이드, HTML 화면을 넘겨 볼 수 있습니다.

### 조작

| | |
|---|---|
| 스페이스 | 재생·정지 |
| ← → | 한 단계씩 앞뒤로 |
| Home / End | 처음으로 / 끝으로 |
| Esc | 뷰어 닫기 |
| 진행 바 클릭 | 그 지점으로 이동 |
| 속도 | 0.5배부터 3배까지 18단계, 기본 1.2배 |

위로 올려 읽는 중에는 화면이 따라 내려가지 않습니다. 다시 바닥에 닿으면 따라가기가 살아납니다.

### 재생 속도

단계마다 화면에 붙는 양이 다릅니다. 도구 한 줄은 스무 자, 최종 답변은 팔백 자가 넘습니다.
모든 단계에 같은 시간을 주면 짧은 줄은 지루하고 긴 답변은 읽을 수 없습니다.
그래서 **방금 붙은 글자 수로 머무는 시간을 정합니다.** 1.0배에서 한 줄은 0.7초,
긴 답변은 4초까지 갑니다.

기본값은 1.2배입니다. 1.0배가 편하게 읽히도록 맞춰 둔 값이고, 발표자가 말을 얹으며
보여 주는 자리라 조금 빠른 쪽이 낫다고 봤습니다. 이 속도에서 회차별 재생 시간은
아래와 같습니다.

| 회차 | 1.2배 |
|---|---|
| 밀린 메일 정리 | 0:18 |
| 주간 업무보고 · 사내 표준 서식 | 0:20 |
| 사내 공지 교열 | 0:29 |
| ISMS-P 심사 대응 | 1:05 |

재생 중에 속도를 바꿔도 그 자리에서 이어집니다. 처음으로 돌아가지 않습니다.

## 재현한 Cowork UI

실제 화면 녹화(13분 52초, 프레임 55장)와 접근성 덤프를 대조해 맞췄습니다.
참고 프레임 6장이 `_작업/frames/`에 있습니다.

| 영역 | 내용 |
|---|---|
| 사이드바 | 채팅·Cowork 토글, 새 작업, 내 작업, 자동화, 사용자 지정, 평면 채팅 목록, 계정 카드 |
| 홈 | "지금 무엇을 작업하고 있나요?", 작업 시작 입력창, 약관 안내, 다음 재생 항목, 시도해 보세요 타일 |
| ＋ 메뉴 | 작업 컨텍스트 추가(Ctrl+/), 이미지 및 파일 업로드(Ctrl+U), 클라우드 파일 및 폴더 첨부(Ctrl+Shift+U), 사용자 지정 |
| 모델 선택기 | 실제 목록. 측정한 모델에는 실측 크레딧, 나머지는 계열과 기본 노력 표시 |
| 노력 선택기 | 가벼움, 보통, 높음, 매우 높음 |
| 컴포저 | ＋, 모델, 노력, 다시 쓰기, 원형 마이크. 재생 중에는 검은 원형 중지와 회색 대기열 pill이 붙음 |
| 홈 힌트 | 입력창 아래 `팁: Ctrl+Shift+U …` 한 줄. 열 때마다 세 가지가 돌아감 |
| 작업 영역 | 단계, 출력, 참조, 기술 및 플러그 인, 도구 |

출력 항목은 **눌러서 바로 열립니다.** 대화 안의 산출물 카드와 같은 뷰어가 뜹니다.
모델을 바꾸면 노력 기본값도 함께 바뀝니다. Claude 계열과 자동은 보통, GPT 계열은 매우 높음입니다.

### 대화 영역에서 특히 주의한 것

실제 화면은 채팅 앱과 구조가 다릅니다.

- **어시스턴트 메시지에 아바타가 없습니다.** 말풍선도 없이 본문이 그대로 흐릅니다
- **사고 과정**은 테두리 없는 작은 회색 토글입니다. 점 하나와 화살표만 붙습니다.
  `생각 중…`은 별도 라벨로 씁니다
- **웹 검색**은 "웹에서 검색함, 결과 N개 찾음" 아래에 쿼리별 결과 수와 URL 목록이 펼쳐집니다
- **파일 검색**은 검색어 옆에 파일·이메일·Teams 같은 소스 배지가 붙습니다
- **도구 호출**은 아이콘 + 회색 동사 + 굵은 대상 한 줄입니다. `폴더 내용 나열 **문서**`
- **여러 도구 호출**은 "작업을 실행하는 중…" 아래로 묶이고 3개까지 보이며 나머지는 "더 보기"
- **문서 편집**은 테두리 없이 흐릅니다. 파일 아이콘(W/P), 굵은 파일명, "편집됨 · N개 편집" 순입니다
  - 같은 종류가 연달아 2개 이상이면 `종류 [N] ›`로 묶여 접힙니다. 펼치면 들여쓰기됩니다
  - **실패는 파일 아이콘 우하단의 붉은 원 배지**입니다. 텍스트 배지가 아닙니다
  - 삽입 내용은 회색 pill, 표 크기는 `· 12×3` 형태로 붙습니다
- **서브 에이전트**는 스피너 + 이름 + 화살표 한 줄입니다. 끝나면 체크로 바뀝니다
- **진행 상태 줄**이 대화 맨 아래에 붙어 문구가 계속 바뀝니다
  ("다음 단계를 실행하는 중", "까다로운 부분을 처리하는 중", "기다려 주셔서 감사합니다.")
- **사용자 프롬프트**는 말풍선 하단 가운데에 "더 보기 / 간단히 보기"가 있고,
  그 아래 오른쪽에 시간, 복사 버튼, 숫자 `99`가 놓입니다
- **재생 중에는 입력창 문구가 "처리 중입니다. 다음 단계는 무엇일까요?"로 바뀌고**
  오른쪽에 검은 원형 중지 버튼과 회색 대기열 pill이 나타납니다. 대기열은 눌리지 않습니다
- **보낼 내용이 없으면 보내기 버튼이 없습니다.** 다시 쓰기 아이콘과 원형 마이크만 남습니다

### 작업 영역

- 상단에 현재 활동 문구가 뜹니다. "Cowork가 …docx을(를) 편집하고 있습니다."
- 단계마다 **완료됨 / 진행 중 / 보류 중** 상태가 붙습니다
- 재생이 끝난 뒤의 상태는 `stepStates`로 실제 실행 기록을 따릅니다.
  Terra 회차는 3단계 중 1개가 **취소됨**입니다
- 도구에는 설명이 함께 나옵니다. "이 작업에 대해 조직의 콘텐츠를 검색함"

## 시나리오 데이터 형식

```json
{
 "id": "tc04-terra", "tc": "TC-04", "folder": "딥리서치",
 "title": "…", "chatTitle": "사이드바·제목줄용 짧은 제목", "subtitle": "…",
 "model": "GPT 5.6 Terra", "effort": "매우 높음", "date": "2026년 9월 2일 수요일",
 "credit": 1614,
 "bench": { "n": 3, "people": 1, "min": 1614, "max": 2126,
            "head": "표 제목(선택)", "lead": "표 설명(선택)",
            "condition": "측정 조건",
            "models": [{"name": "…", "avg": 1614, "n": 1,
                        "effort": "매우 높음", "meta": "87분 · 단계 3 · …"}] },
 "steps": ["작업 영역에 표시할 단계"],
 "stepStates": ["완료됨", "완료됨", "취소됨"],
 "skills": ["Word"], "tools": ["SharePoint"],
 "prompt": "…", "promptTime": "오전 10:24",
 "promptFiles": ["첨부한 파일명.pdf"],
 "refs": ["작업 영역 참조 섹션에 띄울 파일명.pdf"],
 "note": "재생 화면 상단 안내에 덧붙일 한 줄",
 "promptAt": 8,
 "scheduled": { "name": "평일 아침 브리핑", "when": "Every week on Monday, … at 07:30" },
 "allowed": ["메시지 보내기"],
 "log": [ … ],
 "artifacts": [ … ]
}
```

`credit`을 `null`로 두면 "아직 확인하지 않았습니다"로 표시됩니다.
`stepStates`를 빼면 재생이 끝났을 때 모든 단계가 완료됨이 됩니다.
값으로 `완료됨`, `진행 중`, `보류 중`, `취소됨`, `중단됨`을 쓸 수 있습니다.
아직 끝나지 않은 회차는 `진행 중`으로 남겨 둡니다.
**내용이 없는 작업 영역 섹션은 아예 그리지 않습니다.** `steps`가 비면 단계 칸이,
`artifacts`가 비면 출력 칸이, `skills`나 `tools`가 비면 그 칸이 사라집니다.
실제 화면도 그렇습니다. 짧은 작업은 단계 계획을 세우지 않아 단계 칸 자체가 없습니다.
`skillsButton: true`를 주면 스킬이 없어도 기술 및 플러그 인 칸에 **기술 관리** 버튼이 뜹니다.
`promptFiles`는 프롬프트 말풍선 위에 파일 칩으로, `refs`는 작업 영역의
참조 섹션으로 나옵니다. 확장자로 아이콘 색이 정해집니다(docx, pptx, pdf, xlsx·csv, html).
확장자가 없는 산출물은 메일 초안으로 보고 봉투 아이콘을 붙입니다.
`artifacts[].pages`가 비면 뷰어에 이유가 뜹니다. 세 가지로 갈립니다.
`labeled: true`면 "민감도 레이블이 걸려 있어 열지 않았습니다", 종류가 메일이면
"임시보관함에 남아 있습니다", 그 밖에는 "아직 파일을 받아 두지 못했습니다"입니다.
`bench.models`는 크레딧 오름차순으로 넣습니다. 첫 항목이 "가장 적게 든" 기준이 됩니다.
행에 `self: true`를 주면 그 행이 강조됩니다. 모델 비교 표는 고른 모델이 자동으로
강조되지만, 작업끼리 견주는 표는 이 표시로 현재 회차를 가리킵니다.
`ladder.py`에 자동·보통으로 잰 회차 일곱을 모아 뒀습니다. `ladder.bench('회차 이름')`으로
가져다 쓰면 그 행이 강조된 사다리가 나옵니다.
로그가 `final` 없이 끝나면 산출물 카드가 붙지 않습니다. 승인 대기로 멈춘 회차가 그렇습니다.

### 로그 항목 종류

| t | 화면 | 주요 필드 |
|---|---|---|
| `say` | 어시스턴트 본문 | body |
| `final` | 마지막 답변 + 산출물 카드 | body |
| `think` | 접히는 사고 과정 | label, body |
| `tool` | 도구 호출 한 줄 | icon, label, target |
| `tools` | 도구 호출 묶음 | label, items[{icon, label, target}] |
| `search` | 웹 검색 결과 | queries[{q, urls[]}] |
| `find` | 파일·메일·Teams 검색 | q, sources[] |
| `edit` | 문서 편집 | file, kind(`w`/`p`/`h`), failed, items[{k, v, size}] |
| `ask` | 진행 중 되묻기 | body, answerTime, items[{q, options[], picked}] |
| `mail` | 메일 발송 승인 카드 | to, subject, body, files[], chat |
| `schedule` | 되풀이 작업 승인 카드 | name, every, at, where, desc |
| `stage` | 대화 밖 설정 화면 | n, cap, note, screen{nav, title, act, tabs, secs, menu, modal, crumb, body, hl} |
| `confirm` | 도구 실행 승인 카드 | icon, title, rows[[키, 값]], note, ok |
| `approved` | 승인 뒤 남는 줄 | label, sent |
| `prompt` | 같은 작업에서 이어 시킨 프롬프트 | body, time, sep, files[] |
| `cost` | 대화 도중에 찍은 `/cost` | credit, time |
| `cut` | 기록이 끊긴 지점 | body |
| `agent` | 서브 에이전트 | name, state |

`prompt`로 **한 작업에 여러 턴을 담을 수 있습니다.** 첫 프롬프트는 재생 시작 전에 이미 떠 있고,
두 번째부터는 로그 중간에 시간 구분선(`sep`)과 함께 낍니다.
여섯 줄이 넘는 프롬프트는 접히고 "더 보기"가 붙습니다.
`final`에 `out`(산출물 인덱스 배열)을 주면 **그 턴에서 만든 것만** 카드로 붙습니다.
`out`을 빼면 전부 붙고, `[]`를 주면 아무것도 붙지 않습니다.
작업 영역의 출력 목록은 턴과 무관하게 전체를 보여줍니다.

`cut`은 실제 기록이 거기서 끊겼다는 점선입니다. 그 뒤를 지어내지 않았다는 표시입니다.
`cost`는 대화 도중에 `/cost`를 찍은 자리입니다. 재생이 끝난 뒤의 비용 패널과는 별개로,
그 시점의 누적값을 그대로 남깁니다. 마지막 `/cost`는 `run.credit`으로 두고
`run.costTime`으로 시각을 맞춥니다.

`tools`의 items에는 도구 줄뿐 아니라 **사고 과정도 섞어 넣을 수 있습니다.**
`{think: true, body: "…"}` 형태이고, 실제 화면도 도구 줄 사이에 그대로 낍니다.
도구 줄에 `tag`를 주면 오른쪽에 회색 pill이 붙습니다(예: `Outlook`).

`ask`는 질문마다 선택지를 늘어놓고 사용자가 고른 것만 강조합니다.
실제 화면에서는 카드로 뜨고 답한 뒤 값이 남는데, 재생에서는 질문과 답을 한 덩어리로 보여줍니다.

`mail`은 편집 가능한 초안을 그대로 재현합니다. 받는 사람 pill과 지우기 버튼,
참조·숨은 참조 링크, 서식 툴바, 본문, 첨부 카드, 취소·보내기 버튼까지 들어갑니다.
`to`를 비우고 `disabled: true`를 주면 받는 사람 칸이 비고 보내기 버튼이 잠깁니다.
`chat: true`를 주면 Teams 채팅 카드가 됩니다. 제목과 참조 칸이 빠지고 첨부 버튼이 사라지며,
버튼이 "Post message 항상 허용"으로 바뀝니다.
`schedule`은 되풀이 작업을 만들기 전에 뜨는 카드입니다. 반복 주기와 실행 위치를
드롭다운으로 보여주고, 늘어난 작업 설명을 그대로 싣습니다. 시나리오에 `scheduled`를
넣으면 작업 영역에 예약된 작업 칸이 함께 남습니다.
`allowed`를 넣으면 항상 허용됨 칸이 생깁니다. 승인 카드에서 "항상 허용"을 누른 뒤에
남는 목록이고, 그 도구는 다음부터 승인 없이 실행됩니다.
`stage`는 대화 밖 설정 화면입니다. 캡처를 붙이지 않고 같은 톤으로 다시 그립니다.
`hl`에 적은 자리에 붉은 테두리가 갑니다(`nav`, `act`, 탭·행의 `hl: true`, `menuHl`).
`screen.crumb`를 주면 Cowork가 아니라 OneDrive 화면으로 그립니다.
`promptAt`을 주면 그 수만큼 로그를 지난 뒤에 프롬프트 말풍선이 나옵니다.
설치 과정을 먼저 보여주는 회차에 씁니다.
`variants`를 주면 모델 선택기로 답변을 갈아 끼웁니다. 모델 이름을 키로 두고
`{credit, effort, grade, counts, change, body}`를 담습니다. `final` 항목에 `vary: true`를
주면 그 답변이 대상이 됩니다. 측정하지 않은 모델을 고르면 없는 답을 만들지 않고
그렇다고 말합니다.
`confirm`은 메일이 아닌 도구를 실행하기 전에 뜨는 승인 카드입니다. 파일 복사처럼
값을 표로 보여주고 승인을 받습니다. 둘 다 실제 화면에서 사용자가 누르기 전에는 실행되지 않습니다.
`approved`는 사용자가 누른 뒤 남는 "1개 작업 승인됨" 줄이고, `sent`로 그 아래 결과 줄
(`보낸 이메일`, `초안을 보냄` 등)을 붙입니다.

모든 항목에 `time`, `status`(하단 상태 줄), `act`(작업 영역 활동 문구)를 붙일 수 있습니다.

`icon`은 `folder` `file` `check` `search` `web` `newfile` `struct` `warn` `mail` `copy` 중 하나입니다.
`warn`을 쓰면 줄이 붉게 표시되고, `tag`를 함께 주면 오른쪽 pill도 붉어집니다(스킬 로드 실패 등).
`edit`의 `k`는 `단락 삽입` `텍스트 서식 지정` `테이블 삽입` `테이블 셀 설정` `슬라이드 추가`
`차트 삽입` `단락 스타일 설정` `단락 텍스트 설정` `Set doc properties` 등을 받습니다.

`body`는 `**굵게**`, `` `코드` ``, 파이프 표, `### 소제목`, `- 불릿`을 지원합니다.
빈 줄로 문단을 나눕니다. 표는 첫 줄이 머리글, 둘째 줄이 구분선, 나머지가 본문입니다.

## 산출물 미리보기 다시 만들기

PowerPoint는 COM으로 슬라이드를 PNG로 내보내고, Word는 PDF로 바꾼 뒤 PyMuPDF로 렌더합니다.

```powershell
# PPT → PNG
$pp = New-Object -ComObject PowerPoint.Application
$pres = $pp.Presentations.Open("...pptx", $true, $false, $false)
1..$pres.Slides.Count | % { $pres.Slides($_).Export("ppt_$($_.ToString('00')).png","PNG",1000,563) }
$pres.Close(); $pp.Quit()

# Word → PDF → PNG
$w = New-Object -ComObject Word.Application
$doc = $w.Documents.Open("...docx", $false, $true)
$doc.ExportAsFixedFormat("report.pdf", 17)
$doc.Close($false); $w.Quit()
python -c "import fitz; d=fitz.open('report.pdf'); [d[i].get_pixmap(dpi=88).save('doc_%02d.png'%(i+1)) for i in (0,3,8)]"
```

- 익명화만으로 부족한 문서는 내용을 가상 업무로 다시 씁니다. 표 개수, 빈 셀,
  문단 수 같은 **구조는 원본 그대로** 둡니다. 구조가 바로 그 실행의 결과물이라

크레딧을 재지 않았거나 다른 회차와 겹치는 회차 넷을 `_작업/_보류/`로 옮겼습니다.

`badge-check`는 캡처 화면을 대조해 맞췄습니다. 다섯 턴의 프롬프트 전문, 도구 이름과 순서,
사고 과정이 도구 묶음 안에 끼는 구조, 스킬 로드 실패, 메일 초안과 파일 복사 승인 카드의
필드 배치, 승인 뒤 남는 줄, 다섯 최종 답변과 점수표, `/cost` 566·576·789는 모두 실제 기록입니다.
사고 과정 본문은 캡처에 펼쳐진 것이 실제 값이고 나머지는 재구성했습니다.
메일 본문과 최종 답변의 숫자는 첨부한 CSV를 직접 집계해 전부 대조했습니다
(600건 중 164건 누락, 12명 전원, 상위 4명이 119건, 사업장·월별 분포까지 일치).

산출물 HTML 네 개는 실제 파일입니다. `skill-quality-report.html`은 세 번째 턴에서
덮어쓴 98점 판본이라, 두 번째 턴 카드를 눌러도 98점 화면이 나옵니다. 실제 실행에서도
같은 파일을 갱신했기 때문입니다.

`isms-audit`은 두 턴의 프롬프트 전문, 단계 구성, 도구 이름, **편집 실패 15회**,
주소록 조회 실패, 초안 본문, 두 최종 답변, `/cost` 1,130이 실제 기록입니다.
사고 과정 본문은 캡처에 펼쳐진 것이 실제 값이고 나머지는 재구성했습니다.
성공한 편집 블록 중 연달아 나온 것은 읽기 좋게 합쳤습니다. 실패 블록은 하나도 줄이지 않았습니다.
산출물 넷 중 파일 셋은 실제 파일이고 미리보기까지 붙였습니다. 메일 초안은 파일이 아니라
임시보관함에 남은 것이라 카드만 있습니다.
문서에 들어간 숫자는 첨부 CSV를 직접 집계해 맞췄습니다
(위험 12건 = 심각 5·높음 6·보통 1, 체크리스트 15건 = 준비완료 3·진행중 6·미비 6,
접근통제 영역에 R-001·R-003·R-007과 점검 항목 2·3·4가 몰려 있음).
Zava, Fabrikam, Litware는 Microsoft가 예제에 쓰는 가상 회사명이고 담당자도 가상 인물입니다.

작업 도중에 Cowork가 **스스로 단계 순서를 바꿉니다.** 처음에는 공문을 둘째로 잡았다가
Gap 워크북을 둘째로 옮겼습니다. 재생에서는 마지막 상태를 씁니다.
